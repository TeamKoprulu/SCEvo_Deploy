Pre-push checks

One command per front, run from the deploy repo before you push. The checks only read: nothing is built, written or uploaded.

cd D:\SCBW\SCEvo_Deploy
# one post (or no id: every released post)
.\run.cmd check blog evo-update-1_22
.\run.cmd check site
.\run.cmd check launcher
.\run.cmd check assets
.\run.cmd check mods
.\run.cmd check cdn
# assets, mods, cdn, launcher, site
.\run.cmd check all
# skip test suites and payload hashing
.\run.cmd check cdn --quick
# every missing model / texture, not just new ones
.\run.cmd check assets --all

Each line is one of:

ResultMeaning
PASSFine.
WARNPushable, but look at it first (uncommitted work, things not rebuilt).
FAILDon't push. The line says what to run or fix. The command exits with code 1.
INFOContext, e.g. what isn't deployed yet.

The last line sums it up: READY, READY WITH WARNINGS or NOT READY.

Repo paths

The checks find the other repos from deploy-config.json: launcherRepoPath, siteRepoPath, assetUploadsPath, devRepoPath and campaignRepoPath. Without the last four they use the folders next to this repo (..\EvoSite, ..\SCEvo_AssetUploads, ..\SCEvoDev, ..\SCBW_Campaign). The code is tools/check.js.

blog [post-id]

Models and textures

Then it follows every model and texture reference in the dev mods and MP maps (SCEvoDev) and the campaign mods (SCBW_Campaign\SCEvo_CampaignMods):

  • Game data → model: each CModel, its path built from its parent template the way the editor does (Race and other tokens, VariationCount → _00, _01, …).
  • Game data → texture: every other quoted .m3 / .dds / .tga path (icons, wireframes, terrain, lighting).
  • Model → texture: the texture paths stored in each .m3.

A file counts as there when vanilla SC2 has it (the CascView extraction: the folder above mods\liberty.sc2mod from the decal texture setting), any Evo mod has it (usually SCEvo_Assets or SCEvo_CampaignAssets), or, for a map, the map itself. Templates come from SC2GameData.

Only new work is judged: references added or changed since the newest Update-* tag in SCEvoDev and the newest tag in SCBW_Campaign (plus uncommitted work), and anything pointing at a file deleted since then, in either repo. Older problems are only counted; --all lists them all.

CheckFlags
Missing fileFAIL a model game data loads, or a texture a new or changed model uses, exists nowhere; or any reference to a file deleted since the release (e.g. assets moved out of one mod and never added to the other)
Drive-letter pathFAIL a model points at a texture on a drive (F:\Modding\…\File.dds). Re-export it with MoPaQ paths, so it reads Assets\Textures\File.dds. Listed once per model
Wrong pathWARN the path doesn't exist but a texture with that file name does (a subfolder or a doubled Assets/Textures/ in the export). Fix the path in the model or the game data
Unknown game data textureWARN not in Evo or the extracted vanilla files. Vanilla campaign and coop UI art isn't in the core + liberty extraction: extract that part with CascView under the same SC2 folder and it counts
Older problemsINFO how many missing references predate the release tags
