Cloudflare push

Everything the launcher downloads lives in one Cloudflare R2 bucket. The deploy tool uploads it in a fixed order, so the CDN never advertises a file before the file itself is there.

Bucketevo-campaign, through the rclone remote cf (cf:evo-campaign)
Served fromhttps://scevo.download (custom domain, cdnBase in deploy-config.json); fallback https://pub-8a599b66a5cf440ab429113861fd1c21.r2.dev
Layoutpayload/, betapayload/, meleepayload/, betameleepayload/, assets/, launcher/, installer/, manifests/: the same folder names as in this repo

Setup (once per machine)

  • Node 18+ and rclone (winget install Rclone.Rclone).
  • rclone config: a remote named cf with an R2 API token that can read and write the bucket (Cloudflare dashboard → R2 → Manage API Tokens).
  • Copy deploy-config.example.json to deploy-config.json and set the paths (or use the Settings tab).

Steps

  1. Check 
    .\run.cmd check cdn
    R2 credentials, the CDN address, the full preflight of every manifest, and what isn't deployed yet.
  2. Dry runDeploy tab with Dry run ticked, or: 
    .\run.cmd deploy --package campaign --dry-run
.\run.cmd deploy --package melee --dry-run
    The Deploy tab compares each package with the live CDN and ticks the ones with changes. .\run.cmd status prints the same summary.
  3. Deploy 
    .\run.cmd deploy --package campaign
.\run.cmd deploy --package melee
.\run.cmd deploy --package meleebeta
    Several packages can go in one deploy (tick them together in the GUI).
  4. ConfirmThe deploy reads the manifests back from the CDN. Open the launcher and check the update shows.

What a deploy does

  1. Checks rclone and the R2 credentials.
  2. Regenerates the chosen packages' manifests from the catalog.
  3. Preflight: each manifest against the files on disk (size and hash), JSON hygiene, structure, locale strings, version rollback against the live manifest. Errors stop the deploy.
  4. Launcher package only: stages the exes from the launcher repo and writes launcher-version.json.
  5. Uploads the payload folders (rclone copy --checksum; copy, never sync, so nothing remote is deleted).
  6. Postflight: HEAD-checks every file on every CDN address. Missing or wrong-size files stop the deploy before any manifest goes up.
  7. Uploads the manifests last (Cache-Control: no-cache).
  8. Reads the manifests back and compares them.
  9. Optionally updates the website's download links (--update-site).
--force

--force pushes past generate, preflight and postflight errors. Use it only when you know why the check is wrong; a launcher that reads a manifest pointing at a missing file fails the player's update.

News between deploys

For a banner swap or an announcement without a full deploy: News tab → Publish news only. It uploads only news-feed.json and assets/news/, after the news checks pass. Patreon cards copy their image into assets/news/ when you save, so publish (or deploy campaign) after saving.

Uploading a folder by hand

For files no package owns, such as the launcher's match report icons in assets/replay-icons/. A campaign deploy uploads all of assets/, so a manual upload is only needed between deploys. Use the same flags the tool uses:

# preview, then upload
rclone copy "D:\SCBW\SCEvo_Deploy\assets\replay-icons" cf:evo-campaign/assets/replay-icons --checksum --header-upload "Cache-Control: public, max-age=3600" --dry-run
rclone copy "D:\SCBW\SCEvo_Deploy\assets\replay-icons" cf:evo-campaign/assets/replay-icons --checksum --header-upload "Cache-Control: public, max-age=3600" -P

# check one file is live
curl.exe -I https://scevo.download/assets/replay-icons/btn-unit-terran-marine@scbw.png
Never rclone sync

sync deletes remote files that aren't local. One wrong path wipes production. Always copy, and delete remote files only through the Verify tab.

Remote orphans

Files on R2 that no manifest references. Verify tab → pick a branch → review the list → delete only what you confirm. Files outside the package prefixes (like assets/replay-icons/) are not listed there.

Changing the CDN address

  1. Check the new address: Settings → Check, or .\run.cmd cdn-check https://new.host.
  2. Set it as cdnBase (Settings → CDN address).
  3. Deploy the launcher package: launchers learn the address from launcher-version.json. r2.dev stays the fallback.

Full setup: the launcher repo's docs/cdn-custom-domain.md.
