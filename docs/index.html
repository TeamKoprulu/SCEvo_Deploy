Pushing updates

How each part of SC Evo gets from our machines to players: game mods on Battle.net, the launcher's downloads on Cloudflare, the launcher itself, and the website. One page per front, with the commands and the checks to run before each push.

Before any push

Run the check for that front from the deploy repo. It is read-only and ends with READY, READY WITH WARNINGS or NOT READY.

cd D:\SCBW\SCEvo_Deploy
# or: blog [post-id] | site | launcher | assets | mods | cdn
.\run.cmd check all

Details on Pre-push checks. Commands in these pages are written for PowerShell (the VS Code terminal); # lines are comments.

A full patch, in order

  1. Finish and commit the dev workCommit in SCEvoDev (and SCBW_Campaign for campaign changes). The asset check warns about uncommitted dev changes.
  2. Split the assetsPrepare-Upload.ps1, then -Apply, until the dry run reports nothing to do. Commit SCEvo_AssetUploads.
  3. Publish to Battle.netEvery mod the asset report lists under "needs upload", from the SC2 Editor. Tag the release in SCEvoDev Update-<version>, with the version from the patch notes post (the writer picks it); the next asset report compares from that tag.
  4. Package for the launcher.\run.cmd check mods, then Build campaign / melee in the deploy tool and set the versions on the Manifest tab.
  5. Push to Cloudflare.\run.cmd check cdn, deploy with a dry run first, then live.
  6. Patch notes postWrite the post, .\run.cmd check blog <post-id>, release it.
  7. Publish the site.\run.cmd check site, then merge the working branch into main and push.

A launcher release is separate and can go out on its own: Launcher release.
