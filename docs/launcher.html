Launcher release

Players get a new launcher through its self-updater, which only offers a higher version number than the one they have. The deploy tool copies the built exes from the launcher repo and publishes them with launcher-version.json.

RepoD:\EvoLauncher\sc-evo-launcher (launcherRepoPath in deploy-config.json)
Buildsdist-electron\SC Evo Launcher.exe (portable), dist-electron\SC Evo Launcher Setup.exe (installer); Windows 7/8: dist-electron-win7\
PublishedR2 launcher/, installer/, manifests/launcher-version.json

Steps

  1. CommitBuild from whichever branch holds the release, with everything committed, so the exe matches what's in git.
  2. Bump the version 
    cd D:\EvoLauncher\sc-evo-launcher
# package.json + package-lock.json
npm version 1.4.0 --no-git-tag-version
    A rebuilt exe under the same version never reaches players. The check warns about it.
  3. Test and build 
    npm test
# Windows 10/11: portable + installer
npm run build
# Windows 7/8 (Electron 22), optional
npm run build:win7
  4. Check 
    cd D:\SCBW\SCEvo_Deploy
.\run.cmd check launcher
    Version above the live one, build at this version, not a devtest build, Windows 7 build fresh, tests pass.
  5. Dry run, then deploy 
    .\run.cmd deploy --package launcher --dry-run
.\run.cmd deploy --package launcher --update-site
    --update-site (Deploy tab: Update website download links) writes the new links into the site's assets/js/site-links.js and copies launcher-version.json to assets/data/. It needs the Website repo path in Settings (siteRepoPath).
  6. Publish the siteCommit and push those two site files: Website push. Without --update-site, run node scripts/sync-launcher-info.mjs in EvoSite instead.
  7. Patch notesDraft them in the launcher repo's docs/patchnotes-<version>.md, then post them: Blog posts.
Never publish a devtest build

npm run build:devtest turns on DevTools and the debug toolbar, and with it Debug Mode and everything locked behind it (the match analysis: build orders, graphs, insights, replay sharing). Hand devtest exes to testers directly. .\run.cmd check launcher fails on one.

Windows 7/8 build

  • Same code, packaged with Electron 22.3.27 (the last that runs on Windows 7/8). Its package.json gets "channel": "win7", so it only updates from the win7 section of launcher-version.json.
  • It is published only when built at the current version. A stale one is skipped and the live Windows 7 version stays.
  • Main-process code must also run on Node 16: no global fetch, AbortSignal.timeout or Array.prototype.findLast. Network calls go through electron/net.js.

Launcher assets on the CDN

Some launcher art is streamed rather than bundled, so it can change without a release:

WhatBuilt byLives in
Match report unit iconsnode scripts/build-replay-units.js (from SCEvo_Assets.SC2Mod textures, then retail)SCEvo_Deploy\assets\replay-icons\ → R2 assets/replay-icons/
Hero backgroundsThe deploy tool's Manifest tabassets/launcher/
News imagesThe deploy tool's News tabassets/news/

They go up with the Launcher assets package (all of assets\, no manifest), or with a campaign deploy. To ship new art with a launcher release and no campaign deploy:

.\run.cmd deploy --package launcher,assets --dry-run
.\run.cmd deploy --package launcher,assets --update-site

On the Deploy tab, tick Launcher and Launcher assets. The tab and .\run.cmd status compare assets\ with R2 by hash (e.g. "388 new (replay-icons 388)"), and a live deploy checks R2 against the folder again after the upload.
